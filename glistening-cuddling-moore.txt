# Plan: Nemoverse WebGL Hero Overhaul — Image-Driven Particle Morph System

## Context

This plan overhauls the Nemoverse WebGL hero in `nemo-webgl.html` to replace the hardcoded pose geometry and palette with four offline-extracted particle formations (`pose0.json`–`pose3.json`). The new pipeline adds real per-particle color, spring-back physics, fluid cursor response, inertia, shockwaves, camera spin, and edge crossfading. It respects `prefers-reduced-motion` and serves a loading overlay while the JSON data is fetched at runtime.

The plan was developed using the **frontend-design** skill framework and the Nemoverse project's existing architecture, then refined with the user's explicit answers to clarification questions.

## Phase 2: Design

### 2A. File Modifications

The entire implementation lives in `nemo-webgl.html`. Key changes:

1. **Loading overlay** — Add a `.loading-overlay` div covering the canvas, shown during `Promise.all` fetches and hidden on completion or error.
2. **Remove hardcoded data** — Delete `DATA.palette`, `DATA.poseB64`, `DATA.edgesB64`, `DATA.edgeCount`, `decodePose()`, `b64ToBytes()`, and `var STRIDE_F = 13`.
3. **Add JSON fetch** — After the IIFE starts, use `Promise.all([fetch('data/pose0.json'), ..., fetch('data/pose3.json')])` to load the particle data.
   - On failure: display a serving note (`<p>Run with `python3 -m http.server`</p>`)
   - On success: parse JSON, build GPU buffers, hide overlay
4. **22-float vertex stride** — Replace the old 13-float layout with:
   - `aPoseAB` (vec4): 4 floats — pose A's start/end
   - `aPoseCD` (vec4): 4 floats — pose C's start/end
   - `aColA` (vec3): 3 floats — per-pose color A
   - `aColB` (vec3): 3 floats — per-pose color B
   - `aColC` (vec3): 3 floats — per-pose color C
   - `aColD` (vec3): 3 floats — per-pose color D
   - `aMeta` (vec2): 2 floats — seed and size
   - Total: 4+4+3+3+3+3+2 = 22 floats per particle (≈1.7 MB at N=20,000)
5. **Vertex shader** — Updated `VS_PARTICLE` with:
   - Staggered easing: `ti = smoothstep(clamp((uT - seed*0.35)/0.65, 0, 1))`
   - Mix positions and colors between source/destination poses using `ti`
   - Mouse repulsion, shockwaves, camera spin applied in shader
   - Hooke spring forces computed on CPU each frame
6. **CPU physics loop** — Runs each frame:
   - Maintains `Float32Arrays` for `(ox, oy, speed)` per particle
   - Applies Hooke spring forces with seed-based stiffness and damping variance
   - Gaussian cursor repulsion + tangential vortex scaled by pointer velocity
   - Updates dynamic VBO `(ox, oy, speed)` for vertex shader consumption
7. **Click response** — On pointerdown:
   - Radial shockwave impulse at pointer position
   - Advance the morph cycle (`fromPose → toPose`)
   - Camera-spin kick using seed-derived pseudo-depth
8. **Edge generation** — At load time, spatial-hash near-neighbor search generates per-pose edge index buffers. During morphs, crossfade from→to edges with two line draws and `uLineAlpha`.
9. **Bright pass / bloom pipeline** — Unchanged architecture but benefits from new per-particle RGB colors.
10. **Accessibility** — Respect `prefers-reduced-motion`: freeze idle/cycle animation when reduced motion is active. Keep 2.4 s morph / 5.2 s hold cycle otherwise.
11. **Keyboard navigation** — Left/right arrows cycle poses.
12. **Pose indicator dots** — Small UI controls at bottom.

### 2B. Shader Changes Summary

- **VS_PARTICLE**: Receive the 22-float stride. Calculate staggered easing factor `ti`. Mix positions: `base = mix(pFrom, pTo, ti)`. Apply mouse repulsion, shockwave impulse (if active), camera spin, and spring forces from the dynamic VBO. Output `gl_PointSize` with per-particle size modulation.
- **FS_POINT**: Use the per-pose color attributes interpolated via `ti` to shade particles with real RGB color. Keep existing falloff.
- **VS_LINE / FS_LINE**: Two draws per morph segment, crossfaded with `uLineAlpha`. Edge indices generated via spatial hash at load time.
- **setCommonUniforms**: New `uLineAlpha` uniform. Also pass `uReduced` and camera spin state.

### 2C. Physics Model (CPU loop)

```
For each particle i:
  dx = ox[i] - mouseX; dy = oy[i] - mouseY
  dist2 = dx*dx + dy*dy
  // Hooke spring toward rest position
  fx = -k * dx - d * vx[i]
  // Gaussian cursor repulsion
  if dist2 < R_repulse^2:
    fx += repulsion * (dx / dist2)
  // Tangential vortex scaled by velocity
  vx += fx * dt
  // Integrate
  x += vx * dt
  update VBO
```
