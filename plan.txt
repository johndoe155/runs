PROJECT INTENT
Replace the hardcoded pose geometry and palette in the Nemoverse WebGL hero with four offline-extracted particle formations, real per-particle color, and a richer interaction model featuring spring-back, fluid cursor response, inertia, shockwaves, and camera spin.
	

1. Project Goal
The objective is to create a new, self-contained Nemoverse project at ~/nemoverse/ while leaving the original attachment untouched. The new hero will load four particle formations generated from reference artwork and render them through an upgraded WebGL pipeline with expressive, physics-informed motion.

4. Offline Particle Extraction
The extractor runs inside an isolated virtual environment created within the project directory: python3 -m venv .venv && pip install pillow numpy. Each reference image follows the pipeline below.
1. Normalize inputs — Downscale each image so its long edge is no more than 512 pixels.
2. Model the background — Sample the border ring and cluster it into several dominant background colors using a quantized median.
3. Flood-fill definite background — Flood-fill inward from every border pixel when the color falls within the tolerance of the background model.
4. Score candidate foreground — For remaining pixels, combine color distance from the background with saturation weighting and a soft center bias.
5. Apply image-specific rules — Handle the desk, underwater, torn-paper, and street images with tailored hue, tolerance, and bias adjustments.
6. Threshold and retain components — Use an adaptive Otsu threshold on the score map, then retain the largest center-covering connected component or components.
7. Sample particles — Sample 20,000 points by default, with sub-pixel jitter. Record normalized coordinates and per-particle RGB values.
8. Grade color — Apply a gentle gamma lift, saturation boost, and small luminance floor so dark source pixels remain legible against the near-black additive background.
9. Emit data and previews — Write flat rounded JSON arrays and produce mask-overlay and colored-sample QA previews for every pose.
The output schema is {"n": N, "pos": [x0, y0, ...], "rgb": [r, g, b, ...]}. Coordinates use four-decimal precision. The foreground bounding box is uniformly scaled and centered into xrange [-0.36, 0.36], while yrange [-0.03, 1.03] is preserved as required.

7. WebGL Hero Overhaul
Boot and loading
Remove `poseB64`, `edgesB64`, `palette`, and `decodePose`. Fetch `data/pose0..3.json` with `Promise.all`, build GPU buffers, show a loading overlay while awaiting data, and display a serving note when fetch fails because `file://` blocks requests.
Vertex layout
Use a 22-float stride containing `aPoseAB`, `aPoseCD`, four per-pose color attributes (`aColA..aColD`), and `aMeta` for seed and size. The static VBO is approximately 1.7 MB at N = 20,000.
Morph rendering
Select source and destination poses in the vertex shader and mix their positions and colors with staggered easing: `ti = smoothstep(clamp((uT - seed*0.35)/0.65, 0, 1))`. This creates organic scatter instead of a rigid global sweep.
CPU physics
Maintain Float32Arrays and update a dynamic vec3 VBO `(ox, oy, speed)` every frame. Use Hooke spring forces with seed-based stiffness and damping variance, plus a Gaussian cursor repulsion and tangential vortex scaled by pointer velocity.
Click response
Apply a radial shockwave impulse at the pointer, advance the morph, and add a camera-spin kick.
Camera and brightness
Use seed-derived pseudo-depth for eased pseudo-3D yaw. Let pointer rotation carry inertia, and use particle speed to boost point size and brightness into the bloom pass.
Edges
Generate per-pose edges at load time with a spatial-hash near-neighbor search, capped by count and length. During morphs, crossfade from-pose and to-pose edges with two line draws and `uLineAlpha`.
Interaction and accessibility
Keep the 2.4-second morph and 5.2-second hold cycle. Support click/tap anywhere, pose-indicator dots, and keyboard left/right navigation. Preserve `prefers-reduced-motion` by freezing idle and cycle animation.
Performance
Default to N = 20,000 particles and use a simpler mobile fallback constant.
8. Validation Checklist
* Run node --check against the extracted inline script.
* Validate JSON schema: array lengths match, particle count is consistent, and coordinate ranges remain within the defined x/y bounds.
* Serve the project with python3 -m http.server.
* Smoke-test that index.html and all four pose JSON files resolve with curl.
* Perform the final visual check in a WebGL-capable browser; this Termux shell does not provide a WebGL browser. The mask previews and code-level checks are the available verification artifacts here.
